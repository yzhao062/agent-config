## Goal

Ship aa v0.5.0 as a single coherent release that:

1. Closes the v0.4.0 schema-vs-consumption gap by enabling bootstrap-active consumption of inline `source:` URLs in `agent-config.yaml` (both `packs:` and legacy `rule_packs:`).
2. Lands the auth chain (SSH agent → gh CLI → `GITHUB_TOKEN` env → anonymous) so private-source packs work alongside public-source packs through one composer entry point.
3. Wires the three v0.4.0-shipped-but-not-wired primitives (per-user/per-repo locks, orphan reconciliation, 4-layer user-level config resolver) into `compose_packs.py`.
4. Makes `yzhao062/agent-pack@v0.1.0` loadable end-to-end as the v0.5.0 acceptance test — passive (`profile`, `paper-workflow`) and active (`acad-skills`) packs install with one bootstrap.
5. Introduces a **prompt** update policy as the new default: fetch into cache, ask the user to apply, fall back to skip-and-log on non-TTY contexts (with banner-driven awareness).

## Architecture

### Module layout

```
                  ┌──────────────────────────────────────────┐
                  │         compose_packs.py (entry)         │
                  │  ┌───────────────────────────────────┐   │
                  │  │ host = detect_host(env, --host)   │   │  ← new at v0.5.0
                  │  │ outer-lock acquire (Deferral 1)   │   │  ← new at v0.5.0
                  │  │ orphan-reconcile  (Deferral 2)    │   │  ← new at v0.5.0
                  │  │ resolve packs (4-layer + URL val) │   │  ← new at v0.5.0
                  │  │            ↓                      │   │
                  │  │ for pack in selection:            │   │
                  │  │   if entry.source.url:            │   │
                  │  │     archive = source_fetch(...)   │ ──┼──→ source_fetch.py (NEW)
                  │  │     manifest = read(archive)      │   │      └─ wraps auth.fetch_with_auth_chain
                  │  │   else:                           │   │           └─ auth.py (extends v0.4.0)
                  │  │     archive = bundled lookup      │   │                ├ ssh_agent_available()
                  │  │   prompt-or-apply (prompt policy) │   │                ├ gh_cli_authenticated()
                  │  │   dispatch(manifest, archive,host)│ ──┼──→ dispatch.py (existing + host param)
                  │  │   write pack-lock + state         │ ──┼──→ state.py (existing)
                  │  │ end-of-run compose summary        │   │                ├ github_token_available()
                  │  │ write pending-updates.json        │   │                ├ resolve_ref_with_auth_chain
                  │  └───────────────────────────────────┘   │                ├ fetch_with_method(url,ref,M)

                            │
                            └──── pending-updates.json ←── read by session_bootstrap.py
                                                          (printed as compact one-line notice;
                                                           CLAUDE.md banner format also reads it)
```

### Three new layers on the v0.4.0 skeleton

1. **Transport** (`auth.py` extension): pure functions for per-method probes, ref resolution, per-method fetch drivers, and the chain orchestrator. Existing `reject_credential_url`, `noninteractive_fetch_env`, `normalize_github_url` stay untouched and become the input gate.
2. **Source fetch** (`source_fetch.py` NEW): high-level "fetch this pack's content as a local directory". Wraps the orchestrator with cache management (canonical-id + resolved-commit-keyed), pack-lock integrity check, sha256 verification.
3. **Compose entry** (`compose_packs.py` UPDATED): branches on `entry.source.url` presence; calls `source_fetch` for inline source, falls back to bundled lookup otherwise. Acquires outer locks at entry, runs reconciliation, reads selections through the 4-layer resolver with credential-URL validation, detects host identity, prompts the user when drift is found. `compose_rule_packs.py` becomes a thin shim.

### Modules touched at the integration edge

- `passive.py` reads through the archive adapter when `ctx.pack_source_dir` is present; keeps the legacy raw-URL path otherwise.
- `state.py` policy enum and pack-lock validation extended for `prompt` (Round 2 H1: `state.py:77`, `state.py:196`, `state.py:231` hardcode `{"locked", "auto"}` today; must be extended in lockstep with `schema.py` so a defaulted `prompt` policy doesn't fail post-validation at write time).
- `dispatch.py` keeps the existing `current_host` ABI (Round 2 M3); compose supplies the detected value via `DispatchContext(current_host=detect_host(), ...)`.

### Modules untouched

`transaction.py`, `locks.py` (helper unchanged; just *called* now), `reconciliation.py` classifier (unchanged; the new orchestrator wraps it), active handlers, `uninstall.py`, all CLI subcommands (extended; not replaced), `guard.py` (banner integration owned by `session_bootstrap.py`, not `guard.py`).

## Components

### A. `auth.py` extensions (~250 lines added on top of existing 198)

**Per-method probes** (no network, fast):
```python
def ssh_agent_available() -> bool        # ssh-add -l exit 0
def gh_cli_authenticated() -> bool       # gh auth status exit 0
def github_token_available() -> bool     # GITHUB_TOKEN env set + non-empty
```

**Ref resolver** (one network call per call, auth-aware):
```python
def resolve_ref_with_auth_chain(url: str, ref: str,
                                 explicit_method: str | None = None
                                ) -> tuple[str, str]
    # returns (resolved_commit, method_that_succeeded)
    # implementation: git ls-remote <url> <ref> with the same auth chain as fetch_with_method
    # used by source_fetch (for cache lookup), pack list --drift, pack update
```

**Per-method fetch driver** (one `git clone` subprocess each):
```python
def fetch_with_method(url: str, ref: str,
                      method: Literal["ssh","gh","github_token","anonymous"]
                     ) -> PackArchive
```

| Method | `git clone` invocation | Auth shape |
|---|---|---|
| `ssh` | `git clone --depth=1 --filter=blob:none --branch <ref> git@github.com:<owner>/<repo> <dest>` | ssh-agent ambient |
| `gh` | `git -c credential.helper='!gh auth git-credential' clone ...` (https URL) | gh credential helper |
| `github_token` | `GIT_ASKPASS=<helper script> git clone ...` (https URL); helper script outputs `x-access-token` (username) and `$GITHUB_TOKEN` (password) on prompt | **Token never appears in argv.** Helper script lives in tempdir, deleted post-fetch. |
| `anonymous` | plain `git clone --depth=1 --filter=blob:none --branch <ref> https://github.com/<owner>/<repo> <dest>` | (none) |

`--branch <ref>` works for branches and tags. For full-SHA refs, the driver clones the default branch first, then runs `git fetch origin <sha> && git checkout <sha>` — Phase 3 implementation tests both forms.

All four call sites use `noninteractive_fetch_env()` (existing v0.4.0). For `github.com` URLs, `normalize_github_url` swaps URL form per method.

**Orchestrator**:
```python
def fetch_with_auth_chain(url: str, ref: str,
                          explicit_method: str | None = None
                         ) -> PackArchive
```

Walks methods in spec order (ssh → gh → github_token → anonymous), skips methods whose probe fails, returns the first method whose `fetch_with_method` succeeds. With `explicit_method` set, skips the chain — fail-closed if that one method fails. Composite error on full exhaustion lists each attempted method + its failure reason.

**Secret redaction (Round 3 H2)**: applied **before any user-controlled URL, env value, argv, subprocess output, exception text, report object, pending-update file, cache metadata, lock/state file, or bootstrap/session line is rendered or written**. Two helpers:

```python
def redact_url_userinfo(url: str) -> str
    # https://user:pass@host/path → https://<redacted>@host/path
    # https://<token>@github.com/owner/repo → https://<redacted>@github.com/owner/repo
    # ssh://git@host/path → unchanged (transport username, not credential)
    # ssh://user:pass@host/path → ssh://user:<redacted>@host/path

def redact_secret_text(text: str, known_secrets: Iterable[str] = (), token_prefixes: tuple[str, ...] = ("ghp_","gho_","ghu_","ghr_","ghs_","github_pat_","Bearer ")) -> str
    # replace every occurrence of every known secret in text with <redacted>
    # also replace bytes matching any token_prefixes pattern
```

`reject_credential_url(url, source_layer)` (existing v0.4.0 helper at `auth.py:54-105`) **must call `redact_url_userinfo` on the URL before including it in the raised `CredentialURLError` message**. v0.4.0's current behavior echoes the raw URL via `f"... source URL {url!r} contains credentials in userinfo ..."` — that leaks the secret in the rejection message. v0.5.0 fixes this in lockstep with the auth chain landing.

### B. `source_fetch.py` — NEW (~250 lines)

```python
@dataclass(frozen=True)
class PackArchive:
    url: str                     # original URL from agent-config.yaml
    canonical_id: str | None     # canonical github.com identity ("<owner>/<repo>") or None for non-github
    ref: str                     # original ref (tag, branch, sha)
    resolved_commit: str         # 40-char sha (from git rev-parse HEAD or resolve_ref_with_auth_chain)
    method: str                  # which auth method succeeded
    archive_dir: pathlib.Path    # local clone dir
    cache_key: str               # sha256(canonical_id or url)[:16] + "/" + resolved_commit

def fetch_pack(url: str, ref: str, *,
               policy: Literal["auto","prompt","locked"] = "prompt",
               explicit_auth: str | None = None,
               cache_root: pathlib.Path | None = None
              ) -> PackArchive
```

**Fetch ordering** (addresses Codex Round 1 #5):
1. Validate URL via `auth.reject_credential_url` (no network).
2. Resolve ref → `resolved_commit` via `auth.resolve_ref_with_auth_chain`.
3. Compare `resolved_commit` against pack-lock entry; under `policy=locked` and drift, raise `PackLockDriftError` and stop.
4. Cache lookup at `(canonical_id_or_url_hash, resolved_commit)`. Hit → re-verify dir-sha256, return.
5. Cache miss → call `auth.fetch_with_auth_chain` to clone into a staging dir; rename atomically into cache; compute dir-sha256.

**Cache key strategy**: for `github.com` URLs, key by `sha256(canonical_id)[:16]` (so `https://github.com/owner/repo` and `git@github.com:owner/repo` share one cache slot). For other hosts, key by `sha256(url)[:16]` (URL-shape sensitive; no normalization).

**dir-sha256**: stable sort of file paths, hash each file, hash the joined manifest. Recorded as `dir-sha256:<hex>` per existing v0.4.0 schema.

### C. `compose_packs.py` updates (~350 lines added on top of existing 299)

```python
def main():
    host = detect_host()                                                  # NEW (Codex H3)
    with locks.user_lock(timeout=30), locks.repo_lock(timeout=30):        # Deferral 1
        reconciliation.reconcile_orphans(project_root, user_root,         # Deferral 2 (orchestrator wrapper)
                                         locks_held=True)
        resolved_selections = config.resolve_selections(                  # Deferral 3
            user_path, project_path, project_local_path, env_var,
            validate_url_fn=auth.reject_credential_url)                   # Codex H8

        pending_updates = []
        for entry in resolved_selections:
            if entry.has_inline_source:
                archive = source_fetch.fetch_pack(
                    entry.url, entry.ref,
                    policy=entry.update_policy,
                    explicit_auth=entry.auth)
                remote_manifest = schema.parse_manifest(
                    archive.archive_dir / "pack.yaml")
                pack_def = remote_manifest.get_pack(entry.name)
            else:
                pack_def = bundled_manifest.get_pack(entry.name)

            if entry.update_policy == "prompt" and detect_drift(entry, archive):
                pending_updates.append((entry, archive, pack_def))
                continue                                                  # defer dispatch

            ctx = DispatchContext(current_host=host, archive=archive, ...) # uses existing v0.4.0 field
            dispatch.apply(pack_def, ctx)                                  # all-or-nothing transaction

        if pending_updates:
            apply_or_skip = prompt_user_for_updates(pending_updates)      # NEW (prompt policy + banner)
            if apply_or_skip == "apply":
                for entry, archive, pack_def in pending_updates:
                    ctx = DispatchContext(current_host=host, archive=archive, ...)
                    dispatch.apply(pack_def, ctx)
            else:
                write_pending_updates_json(pending_updates)               # banner reads this

        print_compose_summary(resolved_selections, run_outcomes,
                              pending_updates, host)
```

`detect_host()` order: `--host` CLI flag > `AGENT_CONFIG_HOST` env var > `claude-code` default. The default exists for backward compatibility with v0.4.0 callers that don't set the new flag/env. Compose summary always prints the detected/defaulted host so it's visible.

`prompt_user_for_updates()` non-TTY behavior: if `sys.stdin.isatty() and sys.stdout.isatty()`, show batch prompt; otherwise consult `ANYWHERE_AGENTS_UPDATE` env var (`apply` / `skip` / `fail`, default `skip`). On skip, write `pending-updates.json` for banner consumption.

**Partial-success contract**: any failure in `dispatch.apply` for any pack rolls back the whole transaction (Codex M6). Compose summary shows which pack failed; pack-state and pack-lock unchanged from pre-run state.

### H. Reconciliation orchestrator wrapper (~160 lines in `reconciliation.py`, addresses Codex Round 1 M7 + Round 2 H2)

The v0.4.0 classifier (`reconciliation.py:46`) defines six states (`LIVE`, `ROLLBACK_OK`, `ROLLFORWARD_OK`, `PARTIAL`, `DRIFT`, `MALFORMED`) and `scan_orphans()` (`reconciliation.py:268`) returns `OrphanClassification` objects (not `(path, transaction_json)` tuples). The orchestrator wraps these accurately:

Pseudocode using the **shipped v0.4.0 API** (`reconciliation.py:46` for the 6-state enum, `:69` for the `OrphanClassification.label` field, `:268` for `scan_orphans(staging_dirs: list[Path])`, `:291` for `cleanup_staging(staging_dir: Path)`):

```python
def reconcile_orphans(project_root: Path, user_root: Path, *,
                     locks_held: bool = False,
                     drift_callback: Callable[[OrphanClassification], None] | None = None
                    ) -> ReconciliationReport:
    # If locks_held=False, take the same outer locks compose uses, run, release.
    # If locks_held=True, do NOT classify locks held by this process as LIVE:
    #   either pass a self-lock context into classify_orphan() so locks.is_held()
    #   distinguishes self vs foreign (preferred), or perform the live-process
    #   check BEFORE acquiring outer locks (fallback).
    # Build the staging-dirs list expected by scan_orphans() — both per-user and
    # per-repo staging roots: ~/.claude/hooks/*.staging-* and .agent-config/*.staging/
    staging_dirs = collect_staging_dirs(project_root, user_root)
    for orphan in scan_orphans(staging_dirs):
        match orphan.label:                          # NOT orphan.state
            case "LIVE":           pass  # skip; report no action
            case "ROLLBACK_OK":    cleanup_staging(orphan.staging_dir)  # NOT cleanup_staging(orphan)
            case "ROLLFORWARD_OK": cleanup_staging(orphan.staging_dir)
            case "PARTIAL":
                # Reapply only the staged ops whose target still matches recorded
                # pre-state, then cleanup_staging(orphan.staging_dir). If any
                # staged path missing OR any target differs from pre/post state,
                # leave staging in place and call drift_callback with this orphan.
                reapply_partial_or_report_drift(orphan, drift_callback)
            case "DRIFT":          drift_callback(orphan)  # leave staging; blocking
            case "MALFORMED":      drift_callback(orphan)  # leave staging; blocking
    # Returns ReconciliationReport with counts-by-label + blocking-paths list
    # (consumed by compose for banner / pending-updates surfacing).
```

Tests cover all six classifications under both `locks_held=False` and `locks_held=True` (with self-lock-context behavior) on Windows and POSIX.

### I. CLI extensions (~150 lines + packaging changes, addresses Codex Round 1 H2 + Round 2 M5)

- **`pack add <source-url> [--ref REF] [--pack NAME...] [--type skill|rule]`**: when `<source-url>` resolves to a remote `pack.yaml` with multiple packs, the CLI fetches the manifest and writes one user-level selection per remote pack. Default: write all packs unless `--pack NAME` filter. For `yzhao062/agent-pack`, writes three selections (`profile`, `paper-workflow`, `acad-skills`) each pointing at the same `(url, ref)`.
- **`pack update <name> [--ref REF]`**: locked / prompt drift remediation. Reads `pack-lock.json`, runs `resolve_ref_with_auth_chain`, refetches + re-dispatches + rewrites lock entry for that pack only.
- **`pack list --drift`**: read-only audit. Per-pack `resolve_ref_with_auth_chain` against pack-lock; print drift delta.

**Packaging plan (Round 2 M5 + Round 3 H1)**: `packages/pypi/anywhere_agents/cli.py` currently writes a single user-level entry from the URL-derived name (`cli.py:291`). The shipped `pyproject.toml:51` packages only `anywhere_agents`; `scripts/` has no `__init__.py` and is not a Python package; `pyproject.toml:5–52` has no `[project].dependencies` entry for PyYAML. - `packages/npm/package.json`: include the Python module files OR document that the npm shim installs/uses the PyPI wheel that contains them (decide at Phase 9 implementation time; document the choice in CHANGELOG).

**Vendor-sync drift control (Round 4 M2)**: `scripts/packs/{auth,source_fetch,schema}.py` are the **source of truth**. The vendored copies under `packages/pypi/anywhere_agents/packs/` are produced by a build helper (e.g., `scripts/vendor-packs.py` invoked at `python -m build` time, or as a pre-commit hook). **npm packaging policy (Round 4 M3)**: v0.5.0 ships **bootstrap-only on npm**. The npm package continues to ship `bin/`, `README.md`, and `LICENSE` (matching v0.4.0 layout); its `bin/anywhere-agents.js` shim provides the bootstrap entry but **does not include the v0.5.0 `pack add/update/list` subcommands**. Phase 13 documents this split clearly in README + RELEASING. v0.6.0 candidate: full npm pack-management once a package-bundling decision is made (vendor Python at install time, vs. npm-shim that auto-bootstraps the PyPI wheel on first run).

```json
  "host": "claude-code",
  "packs": [
    {"name": "profile", "current": "ab12cd3", "available": "ef45678", "kind": "passive"},
    {"name": "acad-skills", "current": "ab12cd3", "available": "ef45678", "kind": "active"}
  ]
}
```

`session_bootstrap.py` reads this file at next session start. After printing its existing compact bootstrap line, it appends:

```
[anywhere-agents] 2 pack updates pending — profile, acad-skills · run `bash .agent-config/bootstrap.sh` (Linux/macOS) or `pwsh -File .agent-config/bootstrap.ps1` (Windows) interactively to apply.
```

The CLAUDE.md session-start banner format documented at `CLAUDE.md` § "Session Start Check" is updated by Phase 13 (docs phase) to incorporate the pending-updates count into the "Session check" line — the agent reads `pending-updates.json` as part of populating the banner. When other check items are also flagged (e.g., outdated GitHub Actions versions), pending-updates is appended to the semicolon-separated list. Banner stays at six lines + check line.

**Stale-file invariant (Round 3 M4)**: `pending-updates.json` is cleared when **any** of the following empty the pending list:
- Interactive user accepts the prompt and the apply transaction commits.
- `ANYWHERE_AGENTS_UPDATE=apply` runs in non-TTY mode and the apply transaction commits.
- `anywhere-agents pack update <name>` resolves the drift (per-pack apply).
- A subsequent compose run finds zero remaining drift (e.g., upstream rolled back to the recorded commit).

In every case, the file is deleted **atomically before the compose summary returns** (using the same temp-file + rename pattern as state writes). Otherwise `session_bootstrap.py` keeps printing a stale pending-update line after pack-state has already moved forward.

**Cross-platform note**: the apply command in the printed line includes both shell variants (`bash` for POSIX, `pwsh -File` for Windows) so the same line works regardless of the OS the user is on.

## Data flow

### Cold compose (first bootstrap with `agent-pack` declared, prompt policy default)

```
User → bootstrap.sh → compose_packs.py
                        │
                        ├── detect_host() → "claude-code"
                        ├── acquire user_lock + repo_lock                      (Deferral 1)
                        ├── reconcile_orphans(...) [orchestrator]              (Deferral 2)
                        ├── resolve_selections(4 layers, validate URLs)        (Deferral 3 + Codex H8)
                        │
                        ├── for entry in selection (e.g., "profile"):
                        │     ├── fetch_pack(url, ref, policy=prompt):
                        │     │     ├── reject_credential_url(url)              (parse-time)
                        │     │     ├── resolve_ref_with_auth_chain(url, ref)   (network: ls-remote with auth)
                        │     │     │     → resolved_commit
                        │     │     ├── compare against pack-lock; first install = no comparison
                        │     │     ├── cache lookup at (canonical_id, resolved_commit)
                        │     │     ├── miss → fetch_with_auth_chain(url, ref)
                        │     │     │     → git clone subprocess (first auth method that succeeds)
                        │     │     └── PackArchive (resolved_commit, dir-sha256, method)
                        │     ├── parse_manifest(archive/pack.yaml).get_pack("profile")
                        │     ├── first install ⇒ no drift ⇒ apply now (no prompt)
                        │     └── dispatch.apply(pack_def, ctx{host=claude-code, archive})
                        │
                        ├── (acad-skills active path: same shape; passive.py archive adapter for from-paths)
                        │
                        └── print_compose_summary(...)
```

### Warm compose (second bootstrap, cache hit, no drift)

```
User → bootstrap.sh → compose_packs.py
                        │
                        ├── detect_host()
                        ├── acquire locks
                        ├── reconcile_orphans (none expected)
                        ├── resolve_selections
                        │
                        └── for entry:
                              ├── fetch_pack:
                              │     ├── resolve_ref_with_auth_chain → same resolved_commit
                              │     ├── cache hit at (canonical_id, resolved_commit)
                              │     ├── re-verify dir-sha256 (cheap walk)
                              │     └── return PackArchive (no git clone)
                              ├── policy=prompt, no drift ⇒ no-op (state already matches archive)
                              └── compose_summary: "no changes"
```

### Drift detected (ref advanced, prompt policy)

```
User → bootstrap.sh → compose_packs.py
                        │
                        ├── ... [as above through resolve_ref_with_auth_chain]
                        ├── resolved_commit changed from pack-lock recorded value
                        ├── policy=prompt ⇒ append to pending_updates list
                        ├── continue without dispatching
                        │
                        └── after all packs:
                              ├── prompt_user_for_updates:
                              │     ├── if TTY: batch prompt [Y/n/details/specific]
                              │     │     └── on Y: dispatch all pending; clear pending-updates.json
                              │     │     └── on n: write pending-updates.json
                              │     ├── if non-TTY: consult ANYWHERE_AGENTS_UPDATE env (default skip)
                              │     │     └── apply: dispatch all pending
                              │     │     └── skip: write pending-updates.json (banner reads)
                              │     │     └── fail: exit 1 with pack-lock-drift composite error
                              └── compose_summary
```

### Auth chain decision (inside `fetch_with_auth_chain` / `resolve_ref_with_auth_chain`)

```
explicit_auth set?
  yes → probe(method); if fail → fail-closed error
        attempt(method); if fail → fail-closed error
  no  → for method in [ssh, gh, github_token, anonymous]:
          if probe(method) succeeds:
            try attempt(method)
            on success → return
            on fail   → continue chain (token redacted in error capture)
        all exhausted → composite error (each method's status + reason)
```

### Variations (continued)

- **Locked policy + drift**: `git ls-remote` returns different `resolved_commit` than pack-lock recorded → fail closed with `pack-lock-drift` error. No content rewritten until user runs `pack update <name>`.
- **Auto policy + drift**: ref advances; compose summary prints `commit advanced`; pack-lock updates atomically. No prompt.
- **Rollback**: Path 1 calls `anywhere-agents uninstall --all` before re-composing from new upstream. Owner records cleaned, pack-owned files removed where `owners:` empty.
- **Concurrent compose**: first acquires user_lock + repo_lock; second blocks up to 30s; exits 10 (lock-timeout) on timeout.
- **Codex driver**: `AGENT_CONFIG_HOST=codex`; `acad-skills` active entries (declared `hosts: [claude-code], required: false` in agent-pack v0.1.0+) skip with info log; passive entries install normally.

### Transactional state writes

Every state-file rewrite uses the v0.4.0 transaction layer: stage to `.agent-config/<txn-id>.staging/`, fsync, atomic-rename per file. All packs in a compose run share one outer transaction; **any pack failure rolls back the whole run** (Codex M6). Mid-write crash → staging dir survives → next bootstrap reconciles via Phase 7 orchestrator.

## Error handling

### Categories and exit codes

| Category | When | Effect | Exit |
|---|---|---|---|
| Parse-time | Schema invalid; credential URL detected (any config layer); unknown `kind:` / `auth:` / `update_policy:`; ref drift on locked policy | Refuse to proceed; no state writes | 1 |
| Fetch-time | Auth chain exhausted; ref not found; clone times out; archive's `pack.yaml` malformed or missing the named pack | Refuse the run (all-or-nothing); no partial install | 1 (composite message) |
| Cache integrity | Cache hit but `dir-sha256` mismatch | Clear cache entry; one re-fetch retry; second mismatch → fail | 1 |
| Dispatch-time | Same-path / different-content user-level conflict; active entry references missing file | Roll back whole run (transaction semantics) | 1 |
| Prompt-mode non-TTY fail | `ANYWHERE_AGENTS_UPDATE=fail` and drift detected in non-TTY | Exit with `pack-lock-drift` composite error | 1 |
| Lock timeout | Outer user-lock or repo-lock held > 30s | Print holder PID if available; no state change | 10 (existing contract) |
| State drift | On-disk content for a tracked path is neither recorded value nor any prior | Skip path; surface paths in report | 20 (existing contract) |
| Malformed state | `pack-state.json` parse failure | Refuse to compose; suggest manual inspection | 30 (existing contract) |

v0.5.0 doesn't add new exit codes.

### Composite auth-chain error format (with token redaction)

```
Failed to fetch https://github.com/yzhao062/agent-pack@v0.1.0
  ssh         : skipped (ssh-add -l reported no identities)
  gh          : attempted, exit 1
                gh auth git-credential returned no credential for github.com
                (run `gh auth login` to authenticate)
  github_token: skipped (GITHUB_TOKEN env var not set)
  anonymous   : attempted, exit 128
                fatal: could not read Username for 'https://github.com': terminal prompts disabled

Compose run aborted; no packs installed (all-or-nothing).
```

For explicit `auth:`:

```
Failed to fetch ssh://git@github.com/yzhao062/private-skills@main
  Explicit auth: ssh
  ssh: attempted, exit 255 (Permission denied (publickey))

Fail-closed: explicit auth method 'ssh' did not succeed.
Anonymous fallback was disabled by `auth: ssh` in agent-config.yaml.
```

**Token redaction** is applied to all subprocess output captured before display: any `Bearer <40-hex>`, `x-access-token:<token>`, or recognized token-prefix substring is replaced with `<redacted>` before being included in error messages.

### Fail-closed taxonomy

Six places where v0.5.0 refuses to proceed instead of degrading:

1. Explicit `auth: <method>` failure → no fall-through.
2. `update_policy: locked` + resolved_commit changed → `pack-lock-drift` error.
3. Cache `dir-sha256` mismatch → refuse cache; one re-fetch retry; second mismatch fails.
4. User-level same-path different-content conflict → error listing existing owners + their refs.
5. Manifest schema validation failure → reject at parse time.
6. Credential-URL detected in any config layer → reject at parse time (Codex H8).

Drift detected, interactive TTY:

### Carried forward (verify during implementation)

1. **Banner format**: confirm "Session check" line wording fits 6-line banner constraint when many other check items are also flagged. Phase 8 / Phase 13 may tune the exact format; spec wording is the strawman.
2. **agent-pack `update_policy` field**: with `prompt` as the new default, agent-pack's pack.yaml can drop the explicit `update_policy: locked` from `profile` and `paper-workflow` entries. Check during Phase 13 doc work.
3. **`detect_host()` default behavior**: defaults to `claude-code` when neither flag nor env var is set. This is the v0.4.0-compat choice. Verify no consumer relies on a different implicit default.
4. **`pack add` `--type` flag interaction with multi-pack expansion**: when remote manifest has mixed passive + active packs, what does `--type rule` mean? Probably "include passive packs only". Phase 9 nails the precise semantics; spec leaves it as "applies as a filter".
5. **Locked-policy + prompt-policy interaction**: within one compose run, if entry A is `locked` and drifts (fail-closed) and entry B is `prompt` with no drift, the all-or-nothing rule means B isn't applied either (locked-fail aborts the whole run). Document loudly in error message and CHANGELOG.
6. **Bare-SHA fetch behavior on GitHub**: Phase 3 implementation must test `git clone --depth=1 --branch <sha>` failure path and the fallback (clone default branch + `git fetch origin <sha> + git checkout <sha>`). Codex Round 2 noted this as "implementation should still test bare-SHA fetch behavior on GitHub" (verifying Round 1 M5 fix carries through).
