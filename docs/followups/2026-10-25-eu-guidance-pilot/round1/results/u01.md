Conclusion: Fix F1, F3, and F7 because they protect user data, privacy, and core functionality; decline F2, F4, F5, and F6 because they address rare or harmless edge cases that do not justify added complexity.

- F1: Fix — Silent overwrite of local edits in `docs/notes/` destroys user work whenever someone edits a synced note in the project, which violates user-data safety.
- F2: Decline — A simultaneous network disconnect and full local disk is an extreme compound edge case, and the next session start will overwrite the partial copy anyway.
- F3: Fix — Skipping subfolders breaks documented behavior and causes most of the user's notes to be omitted from the sync.
- F4: Decline — Newline characters in Markdown file names are practically nonexistent in normal usage and only affect log formatting.
- F5: Decline — Concurrent copies writing identical note content produce the same final files without harming accuracy or user data.
- F6: Decline — `.sync-state.json` is an internal state file rather than a user-edited file, and stopping with a traceback on manual corruption is an acceptable failure mode.
- F7: Fix — Leaving deleted notes in a publicly published `docs/notes/` folder leaks private information that the user intentionally removed.
